# Ω درع استمرارية حكيم ومنع الانحدار

الإصدار: ١٫٠  
الحالة: ACTIVE_VERIFIED  
النطاق: حكيم الواحد فقط.

## الغاية

حماية كل خدمة وميزة وعقد وسلوك وأثر نجاح مثبت في حكيم أثناء التطوير والتحديث والتحسين، مع السماح بالتطور الحقيقي وعدم تجميد التنفيذ القديم أو إعادة إدخال مسار أضعف أو أخطر.

الحماية تكون **للغاية والعقد والسلوك المثبت** لا لشكل الكود. يجوز تغيير التنفيذ كليًا إذا بقيت النتيجة المطلوبة محفوظة أو استُبدلت بنتيجة أعلى مثبتة بلا انحدار.

## القاعدة العليا

أي تغيير يلامس قدرة مثبتة يمر حتمًا بالسلسلة:

`DISCOVER → CLASSIFY → PRESERVE_OR_SUPERSEDE → TEST → ADVERSARIAL_CHECK → COMPATIBILITY → ROLLBACK → REGRESSION → RELEASE`

وأي فقد غير معلن أو تدهور غير مبرهن أو حذف اختبار/خدمة/عقد محمي يؤدي إلى `FAIL_CLOSED / NO_RELEASE`.

## طبقات الحماية

١. **P0 — ثوابت لا تُضعف**: الحقيقة، الأمان، الحقوق، عدم ادعاء نجاح غير مثبت، عدم تسريب الأسرار، الوضع المالي الآمن، أقل صلاحية، حكيم الواحد، العربية الافتراضية، حفظ النجاحات المثبتة، الاستعادة والتراجع.

٢. **P1 — قدرات وعقود تشغيلية**: الخدمات، البروتوكولات، نقاط الدخول، واجهات البرمجة، مسارات التحكم، الحالة الدائمة، الاستمرارية بعد إعادة التشغيل، بناء وإصدار Android، الذكاء والمفاضلة والتنفيذ الحي.

٣. **P2 — تحسينات قابلة للتبديل**: تفاصيل التنفيذ الداخلية والتحسينات غير العقدية. يمكن تغييرها بحرية ما دام P0/P1 والنتيجة الفعلية لا تنحدر.

## حالات القدرة

- `PROTECTED_ACTIVE`: قدرة حالية يجب أن تبقى أو تُستبدل رسميًا.
- `PROTECTED_HISTORICAL`: نجاح مثبت يجب حفظ نسبه ودليله، حتى لو لم يعد المسار الحاكم.
- `SUPERSEDED`: استُبدلت بقدرة أعلى مع دليل تكافؤ/تحسن وترحيل وتراجع.
- `RETIRED_SECURITY_DENY`: مسار أُلغي لأسباب أمنية/حقوقية ويجب منع عودته، لا حمايته كوظيفة نشطة.

## عقد التغيير

حذف أو إعادة تسمية أو إزالة عقد/اختبار/خدمة/رمز عام محمي لا يُسمح به بصمت. يلزم سجل انتقال صريح يحدد:

- الهدف القديم.
- النمط: `SUPERSEDE` أو `RETIRE`.
- السبب المادي.
- البديل عند الاستبدال.
- اختبارات الإثبات.
- خطة التراجع أو الاحتواء.
- سلطة التغيير ومصدره.
- حالة اعتماد صريحة.

الاستبدال لا يعني النجاح تلقائيًا؛ لا يصبح البديل خط أساس إلا بعد البوابات والنتيجة الفعلية.

## ما يحميه الدرع

- النواة والحوكمة والمؤشر النشط وتسلسل الاستعادة.
- كل `PROVEN_SUCCESS` ونسب الترقيات والأدلة التي اجتازت PASS.
- اختبارات الانحدار والعقود وعدم حذفها بصمت.
- مسارات التشغيل الحي والحالة الدائمة والاستعادة بعد إعادة التشغيل.
- واجهات Python العامة المختارة كواجهات عقدية.
- Android: المكونات والأذونات والعقود والبناء والإصدار وسلامة المصدر.
- النقل المشفر، الرفض السلبي، عدم إعادة إدخال نقل عام أو صلاحيات Android خطرة.
- الوضع المالي الآمن وأقل صلاحية.
- الذكاء التكيفي، نسيج الذكاء، أفضل مسار، بوابات القيمة.
- العربية والسياق الحاكم وعدم خلط النجاح المخبري بالتأهيل الفيزيائي.
- الاستمرارية السحابية لحكيم نفسه: سلامة SQLite، اللقطات المتسقة، البصمة، الرجوع إلى أحدث لقطة سليمة، والفشل المغلق، وفق `governance/HAKIM_CLOUD_CONTINUITY_AR.md`.

## الاستمرارية السحابية تحت الدرع

`cloud_runtime_continuity` قدرة `P0 / PROTECTED_ACTIVE` وليست وكيلًا ثانيًا. يحمي الدرع مواصفتها ومشغلها واختباراتها وWorkflow الاستمرارية. الـcache وسيط احتفاظ فقط وليس دليل سلامة؛ لا يُقبل حفظ حالة جديدة في الدورة السحابية إلا بعد نجاح ختم الاستمرارية وفحص SQLite وإنشاء لقطة موثقة بالبصمة. يمنع العقد فتح ingress عام للهاتف أو استخدام GitHub كناقل أوامر عام للهاتف أو إنشاء remote shell عام. ولا تتحول القدرة إلى `PROVEN_SUCCESS` تاريخي إلا بعد نجاح التحقق الحي بعد الدمج على `main`.

## منع الانحدار الصامت

يقارن الدرع الحالة الحالية بالحالة السابقة عند توفر Git history. ويمنع، ما لم يوجد انتقال معتمد:

- إسقاط عنصر من `proven_success`.
- حذف نسب ترقية مثبتة أو إعادة كتابة نسبها التاريخي بصمت.
- تحويل دليل `PASS` مثبت إلى حالة أضعف أو حذفه.
- حذف ملف اختبار أو Workflow أو ملف محمي.
- حذف دالة/صنف عام من سطح عقدي مختار.
- حذف مكوّن/إذن Android عقدي بصمت.

## منع التحسين الزائف

الزيادة في عدد الملفات أو الاختبارات أو الميزات لا تعني تحسنًا. الحكم هو حفظ العقد + اجتياز الاختبارات + عدم الانحدار + تحقق الناتج الفعلي حيث ينطبق.

## الاستدامة

للدرع بوابة مستقلة تعمل على كل تحديث وطلب دمج، بالإضافة إلى مروره ضمن منظومة الحوكمة العامة. ويُختبر باختبارات طفرات عكسية تثبت أنه يرفض فقد نجاح مثبت أو خفض PASS أو حذف عقد محمي، وأنه يسمح بالتطور فقط عبر انتقال مصرح ومثبت.

## قاعدة الإصدار

`ANY_UNACCOUNTED_PROTECTED_LOSS → FAIL_CLOSED → NO_RELEASE`

`PRESERVED_OR_PROVEN_SUPERSEDED + ALL_GATES_PASS → ELIGIBLE_FOR_RELEASE`
