# Ω CONSTITUTION AMENDMENT PROTOCOL

هذا البروتوكول يحمي `OMEGA_SOVEREIGN_OPERATING_CONSTITUTION.md` من الانحدار أثناء التطوير. هو تابع للدستور ولا يمنح نفسه سلطة أعلى من النظام/السياسات/تعليمات المستخدم الأحدث المشروعة.

## قاعدة التعديل

لا يُعدّل ركن أو فرض حاكم لمجرد تحسين الصياغة أو إضافة قدرة. أي تعديل جوهري يجب أن يثبت قبل الدمج:

1. **سبب التغيير**: خلل مثبت، تعارض حقيقي، أو قيمة جديدة لا يمكن تحقيقها بملحق مجال.
2. **حفظ العقد**: الغاية، السلطة البشرية، الدليل، حماية الناجح، أقل كلفة كاملة، والاستمرار لا تُضعف.
3. **فصل الطبقات**: لا تدخل SHA أو blocker أو جهاز أو مشروع أو حالة CI آنية إلى الدستور العام.
4. **Impact Diff**: ما الذي تغير دلاليًا؟ ما الذي لم يتغير؟ ما المخاطر الجديدة؟
5. **Regression Gate**: اختبارات عقدية آلية + أي اختبار مجال متأثر.
6. **Head identity**: الـhead المختبر هو نفسه المراد دمجه.
7. **Post-merge verification**: إعادة التحقق على `main` بعد الدمج.

## رتب التغيير

- **PATCH**: تصحيح لغوي/توضيح لا يغير المعنى أو السلطة.
- **MINOR**: إضافة فرض/قاعدة جديدة متوافقة لا تلغي نجاحًا مثبتًا.
- **MAJOR**: تغيير معنى ركن أو ترتيب سلطة أو Human Gate أو معيار قبول؛ يحتاج دليلًا أقوى ومراجعة أثر صريحة.

## قواعد مانعة

- لا تستخدم `STATE CAPSULE` كدليل لتعديل الدستور.
- لا تجعل نجاح أداة واحدة سببًا لإزالة fallback أو استقلال مثبت.
- لا تجعل تحسين القدرة مبررًا لزيادة العبء/المخاطر دون عائد مثبت.
- لا تخفض متطلب PROVEN إلى مجرد “يبدو ناجحًا”.
- لا تحذف Human Gate أو Protected Invariant إلا بدليل مباشر وموافقة لازمة.

## الإغلاق

أي تعديل دستوري لا يملك سببًا مثبتًا + اختبارات + تحققًا بعد الدمج يبقى `NOT_PROVEN` ولا يصبح Canonical.
